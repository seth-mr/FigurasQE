== Diagrama de Despliegue Docker

Esta vista muestra el despliegue local del sistema usando Docker Desktop en Windows. Los contenedores se ejecutan de forma independiente y publican puertos hacia la maquina host. Como los servicios se levantan desde distintos `docker-compose.yml`, la comunicacion entre contenedores usa `host.docker.internal` y los puertos publicados en Windows.

=== Acceso a Servicios

La siguiente tabla resume como se accede a cada componente desde Windows y como se referencia desde otros contenedores Docker. En este despliegue, los contenedores se comunican usando `host.docker.internal` porque los servicios estan publicados hacia el host.

[cols="1,2,2,2", options="header"]
|===
| Servicio o contenedor
| Acceso desde Windows
| Acceso desde Docker
| Uso principal

| `fqe-gateway`
| `http://localhost:3000`
| `http://host.docker.internal:3000`
| Punto de entrada para clientes web, Android y WPF.

| `fqe-auth-service`
| `http://localhost:5041`
| `http://host.docker.internal:5041`
| Autenticacion, registro y emision de JWT.

| `fqe-microservicio-figuras`
| `http://localhost:5124`
| `http://host.docker.internal:5124`
| Datos educativos: estudiantes, tutores, sesiones, niveles y resultados.

| `fqe-logs-service`
| `http://localhost:5186`
| `http://host.docker.internal:5186`
| Consulta de logs y canal WebSocket de eventos.

| `fqe-rabbitmongo-listener`
| `http://localhost:5190`
| `http://host.docker.internal:5190`
| Monitoreo del worker que consume RabbitMQ y persiste eventos en MongoDB.

| `fqe-hands-detection`
| `localhost:50051`
| `host.docker.internal:50051`
| Servicio gRPC usado por el Gateway para deteccion de manos.

| `postgres-db`
| `localhost:5432`
| `host.docker.internal:5432`
| Base de datos relacional PostgreSQL.

| `mongo-logs`
| `localhost:27017`
| `host.docker.internal:27017`
| Base de datos documental para logs.

| `rabbitmq`
| `amqp://localhost:5672` y `http://localhost:15672`
| `amqp://host.docker.internal:5672`
| Mensajeria AMQP y consola de administracion RabbitMQ.
|===
